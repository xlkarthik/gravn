# Decisions

Open decisions and their proposed defaults live in [plan/ref-decisions-risks.md](plan/ref-decisions-risks.md).
This file records what was actually decided or assumed while building, with the date and reason.
"Assumed" entries are reversible defaults the founder hasn't confirmed yet.

| ID    | Decision                                                                                                                                                                                                 | Date        | Status            | Reason                                                                                                                                                      |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-01a | Product name **Gravn**                                                                                                                                                                                   | 10 Oct 2026 | Decided           | See plan.                                                                                                                                                   |
| D-01  | Bundle/application ID `app.gravn.mobile` (with `.dev` and `.preview` suffixes)                                                                                                                           | 16 Oct 2026 | Assumed           | Plan default for gravn.app. **Confirm before the first store upload; it can never change after.**                                                           |
| D-02  | pnpm 12 workspaces, isolated linker                                                                                                                                                                      | 16 Oct 2026 | Decided           | Plan default; Expo SDK 58 bundles cleanly with it and `expo-doctor` passes.                                                                                 |
| D-04  | Business documents stay in the project folder but are git-ignored                                                                                                                                        | 16 Oct 2026 | Assumed           | The repo root is the project folder; `.gitignore` excludes the PDFs, decks, logos and `archive/`.                                                           |
| D-26  | One person can hold several roles in one workspace                                                                                                                                                       | 16 Oct 2026 | Decided           | Stored as a `roles` array (D-41).                                                                                                                           |
| D-40  | **Android and web first; iOS later**                                                                                                                                                                     | 16 Oct 2026 | Decided (founder) | Founder's call. iOS config stays in `app.config.ts`, but no iOS builds or testing for now. This changes the plan's "test both phones from Part 1" rule.     |
| D-41  | Roles are an array column on `workspace_members`, not a `member_roles` table                                                                                                                             | 16 Oct 2026 | Decided           | One row per membership: simpler policies, no join, same expressiveness.                                                                                     |
| D-42  | RLS helper functions live in a `private` schema                                                                                                                                                          | 16 Oct 2026 | Decided           | Policies can call them, but the Data API (which exposes only `public`) can't.                                                                               |
| D-43  | Auth email links go to the web app's `/auth/confirm`, which verifies the token and continues to `next` (a web page or an app link such as `gravn://invite/<token>`)                                      | 16 Oct 2026 | Decided           | One verification path for both apps, so there's no token handling on the phone. Universal and app links (Part 3) can open the app directly later.           |
| D-44  | In Part 1, invitation links are shared by the inviter (copy or share sheet) rather than emailed                                                                                                          | 16 Oct 2026 | Decided           | Emailing needs custom SMTP (Resend, Part 3). Links are still bound to the invited email and expire after 7 days.                                            |
| D-45  | Expo SDK 58 (the plan said 57), TypeScript 6.0 (Expo's pin), Next.js 16.4, ESLint 9                                                                                                                      | 16 Oct 2026 | Decided           | Latest stable at build time. ESLint 10 breaks `eslint-plugin-react`.                                                                                        |
| D-46  | One `packages/shared` package (types, schemas, API, roles, i18n, tokens) instead of three                                                                                                                | 16 Oct 2026 | Decided           | KISS. Split later only if a part needs it.                                                                                                                  |
| D-47  | No react-hook-form. Web uses server actions with `useActionState`; mobile uses a small `useForm` hook. Both validate with the shared zod schemas.                                                        | 16 Oct 2026 | Decided           | The forms are small; less to learn and upgrade.                                                                                                             |
| D-48  | Dark theme only at launch                                                                                                                                                                                | 16 Oct 2026 | Assumed           | Matches the brand. Light mode can come later through the tokens.                                                                                            |
| D-49  | A trainer who invites a member is assigned as that member's trainer on accept                                                                                                                            | 16 Oct 2026 | Assumed           | Lets trainers onboard clients without waiting for the owner.                                                                                                |
| D-50  | Re-inviting the same email cancels the older link; invitations last 7 days                                                                                                                               | 16 Oct 2026 | Assumed           | One live link per person per workspace.                                                                                                                     |
| D-51  | Next.js Cache Components off                                                                                                                                                                             | 16 Oct 2026 | Decided           | Every dashboard page is per-user and dynamic.                                                                                                               |
| D-52  | The phone caches the access list (workspace names and roles only) so the app opens offline; it's rechecked on every foreground and reconnect                                                             | 16 Oct 2026 | Decided           | Plan's offline rules. No health or contact data in that cache.                                                                                              |
| D-53  | No plural forms in strings yet                                                                                                                                                                           | 16 Oct 2026 | Assumed           | i18next needs `Intl.PluralRules`; verify Hermes on Android supports it before relying on it.                                                                |
| D-54  | Rosters show names, not email addresses, in Part 1                                                                                                                                                       | 16 Oct 2026 | Assumed           | Emails live in `auth.users`. Owner access to contact details (permissions matrix) comes with Part 3 owner basics.                                           |
| D-55  | `onboarded_at` on profiles records the first-run choice                                                                                                                                                  | 16 Oct 2026 | Decided           | "Training on my own" needs to be remembered; creating or joining a workspace also sets it.                                                                  |
| D-56  | Coach workspace creators get `{owner, trainer}` roles; gym owners can toggle the `trainer` role on themselves (`set_owner_trainer`) and switch between Owner and Trainer shells                          | 25 Oct 2026 | Decided (founder) | Independent coaches train their own clients, and gym owners who also coach need access to the trainer shell.                                                |
| D-57  | Invitations tied to a `client_record` can be created without an email address and claimed once by any verified user; claiming copies `client_records.display_name` when `profiles.display_name` is blank | 25 Oct 2026 | Decided (founder) | Matches WhatsApp-first onboarding in Indian gyms where the member's sign-up email isn't known upfront.                                                      |
| D-58  | Web dashboard (`/w/[id]`) is open to both owners and trainers (`isStaff`)                                                                                                                                | 25 Oct 2026 | Decided (founder) | Lets trainers and coaches manage clients and build programs on desktop, while RLS restricts trainers to their assigned clients and own invitations/records. |
| D-59  | Part 2 offline sync uses idempotent operations (`sync_operations`) + Last-Write-Wins (LWW) per set/session; no 3-way conflict resolution UI on mobile                                                    | 25 Oct 2026 | Decided (founder) | Sessions are logged by one user on one phone; revision mismatches are logged to `sync_conflicts` for diagnostics without blocking Part 2 on conflict UI.    |
| D-60  | Part 2 local SQLite encryption reuses AES-GCM (`expo-crypto` + key in `expo-secure-store`) on sensitive payloads rather than native SQLCipher                                                            | 25 Oct 2026 | Decided (founder) | Same pattern as session storage; avoids native SQLCipher build issues across Expo SDK upgrades.                                                             |
| D-61  | Part 2 pilot workout logger ships core tracking types (`weight_reps`, `reps`, `time`), core set types (`warmup`, `working`, `failure`), straight sets + supersets, and mid-workout exercise additions    | 25 Oct 2026 | Decided (founder) | Keeps the database schema general while deferring complex pyramid builders and retroactive streak recomputation until after pilot trainer feedback.         |
